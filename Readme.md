# Мохнатые друзья: Telegram-бот для студии выгула собак

Бот для студии выгула собак «Мохнатые друзья». Клиенты смотрят услуги и цены, записываются на выгул и получают ответы без переписки в личных сообщениях. Владелица получает уведомления о новых записях и управляет услугами и записями через встроенную админ-панель.

## Возможности

### Для клиентов

- Приветствие и главное меню из кнопок: «Услуги и цены», «Записаться на выгул», «Связаться с владелицей».
- Список услуг с ценами.
- Пошаговая запись на выгул: имя питомца, дата, время.
- Выбор только свободных дат и времени. Воскресенье выходной.
- Защита от двойной записи: если время уже занято, клиент получает понятный отказ.

### Для администратора

- Команда `/admin` открывает панель администратора. Доступна только пользователю с ID из `ADMIN_ID`.
- Просмотр всех записей.
- Удаление записи по номеру.
- Добавление, изменение и удаление услуг.
- Уведомление в отдельный чат о каждой новой записи.

## Стек

- Python 3.11+
- [aiogram 3](https://docs.aiogram.dev/) для работы с Telegram Bot API
- SQLite (встроенная в Python база данных, файл `data.db`)
- python-dotenv для чтения настроек из файла `.env`
- Docker для запуска в контейнере (необязательно)

## Установка без Docker

1. Клонируй репозиторий или скопируй папку проекта:

   ```bash
   git clone <адрес репозитория>
   cd mohnatye_druzya
   ```

2. Создай и активируй виртуальное окружение:

   ```bash
   python -m venv venv
   # Windows
   venv\Scripts\activate
   # macOS / Linux
   source venv/bin/activate
   ```

3. Установи зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Создай файл `.env` на основе `.env.example` и заполни его (см. раздел «Настройка окружения»).

5. Запусти бота:

   ```bash
   python main.py
   ```

Пока терминал открыт, бот работает. Чтобы остановить его, нажми `Ctrl+C`.

## Установка и запуск через Docker

Docker упаковывает бота вместе с Python и библиотеками, поэтому не нужно ставить окружение вручную. 

### Требования

- Установленный [Docker Desktop](https://www.docker.com/products/docker-desktop/) (на Windows потребуется WSL 2).
- Файл `.env`, заполненный по образцу `.env.example`.

### Перед запуском

Останови бота, если он запущен через `python main.py`. Telegram не даёт двум экземплярам бота с одним токеном получать сообщения одновременно: второй выдаст ошибку `Conflict: terminated by other getUpdates request`.

### Сборка образа

Из папки проекта выполни:

```bash
docker build -t mohnatye-druzya .
```

Точка в конце обязательна. Сборка нужна один раз и заново только после изменений в коде или зависимостях.

### Запуск контейнера

Папка `data` в проекте связывается с папкой `/app/data` внутри контейнера. Так файл базы данных лежит на твоём компьютере и не удаляется вместе с контейнером.

**Windows (PowerShell):**

```powershell
mkdir data
docker run -d --name druzya-bot --env-file .env -v "${PWD}/data:/app/data" --restart unless-stopped mohnatye-druzya
```

**macOS / Linux:**

```bash
mkdir -p data
docker run -d --name druzya-bot --env-file .env -v "$(pwd)/data:/app/data" --restart unless-stopped mohnatye-druzya
```

### Управление контейнером

```bash
docker ps                   # список запущенных контейнеров
docker logs -f druzya-bot   # логи в реальном времени (выход: Ctrl+C, контейнер не остановится)
docker stop druzya-bot      # остановить
docker start druzya-bot     # запустить снова
docker rm druzya-bot        # удалить контейнер (данные в папке data сохранятся)
docker exec druzya-bot ls -la /app/data   # проверить, что файл базы на месте
```

Если нужно обновить бота после изменения кода: останови и удали контейнер, пересобери образ командой `docker build` и запусти заново командой `docker run`.

## Настройка окружения

Все секреты и настройки хранятся в файле `.env`. Он не должен попадать в git и в открытый доступ.

Пример содержимого `.env.example`:

```env
# Токен бота, который выдаёт @BotFather
TOKEN=ВСТАВЬ_СЮДА_ТОКЕН

# Числовой ID администратора (узнать можно у @userinfobot)
ADMIN_ID=123456789

# ID чата или группы, куда приходят уведомления о новых записях
# Для групп ID обычно отрицательный, например -1001234567890
ADMIN_CHAT_ID=-1001234567890

# Юзернейм владелицы для кнопки «Связаться с владелицей»
ADMIN_USERNAME=@username_владелицы
```

| Переменная       | Обязательна | Назначение                                                                 |
|------------------|-------------|----------------------------------------------------------------------------|
| `TOKEN`          | да          | Токен бота от @BotFather                                                   |
| `ADMIN_ID`       | да          | ID администратора, у которого есть доступ к `/admin`                       |
| `ADMIN_CHAT_ID`  | да          | Куда отправлять уведомления о новых записях                                |
| `ADMIN_USERNAME` | нет         | Юзернейм, который показывается клиентам. Если не задан, клиенты видят заглушку |
| `DB_PATH`        | нет         | Путь к файлу базы. По умолчанию `data.db` рядом с кодом. В Docker задаётся в `Dockerfile` |

Если `ADMIN_ID` или `ADMIN_CHAT_ID` не заданы или содержат не число, бот упадёт при старте.

## База данных

Файл базы создаётся автоматически при первом запуске, а таблицы создаются функцией `init_db()` в `db.py`.

**orders** (записи на выгул)

| Поле              | Тип                        | Описание                        |
|-------------------|----------------------------|---------------------------------|
| `id`              | INTEGER, PK, автоинкремент | Номер записи                    |
| `client_name`     | TEXT                       | Имя клиента из Telegram         |
| `client_username` | TEXT                       | Юзернейм клиента или заглушка   |
| `dog_name`        | TEXT                       | Имя питомца                     |
| `date`            | TEXT                       | Дата в формате `YYYY-MM-DD`     |
| `time`            | TEXT                       | Час начала выгула               |

Ограничение `UNIQUE(date, time)` не даёт записать двух клиентов на одно время, даже если они нажали кнопку одновременно.

**services** (услуги)

| Поле    | Тип                        | Описание      |
|---------|----------------------------|---------------|
| `id`    | INTEGER, PK, автоинкремент | Номер услуги  |
| `name`  | TEXT                       | Название      |
| `price` | INTEGER                    | Цена в рублях |

Услуги добавляются через админ-панель, отдельной миграции не требуется.

Файл `data.db` содержит персональные данные клиентов. Не коммить его в git и не передавай третьим лицам.

## Рабочее время

- Рабочий день: с 8:00 до 16:00. Последняя запись возможна на 15:00, чтобы выгул успел закончиться до конца дня.
- Записаться можно на ближайшие 14 дней.
- Воскресенье выходной.

Значения задаются в `handlers/main_handlers.py` (`work_time_start`, `work_time_end`) и в `keyboards/keyboards.py`.

## Использование

### Клиент

1. Пишет боту `/start`.
2. Выбирает «Услуги и цены», «Связаться с владелицей» или «Записаться на выгул».
3. При записи вводит имя питомца, выбирает дату и время. После этого получает подтверждение, а владелица получает уведомление.

### Администратор

1. Пишет боту `/admin`.
2. Выбирает раздел:
   - **Посмотреть записи**: список всех записей, кнопка удаления записи по номеру.
   - **Изменить услуги**: список услуг, кнопки удаления, изменения и добавления.

Обычные пользователи не видят админ-панель: на команду `/admin` бот не отвечает.

## Известные ограничения

- Список записей показывает все заказы за всё время, а не только будущие.
- Если у клиента нет юзернейма, владелице сложно с ним связаться. В планах: сохранять `user_id` и давать ссылку на профиль.
- Длинный список записей может не поместиться в одно сообщение Telegram (лимит 4096 символов).

## Планы развития

- Показывать только будущие записи и разбивать длинные списки на части.
- Сохранять `user_id` клиента вместо юзернейма.
- Выложить бота на сервер (VPS) и запускать через `docker compose`.
